# SAG CE — налаштування каналів через вебконсоль

Увійдіть під Superadmin з підтвердженим MFA, відкрийте **Канали сповіщень**
(шлях `/admin/alert-channels`), виберіть потрібний канал, заповніть
параметри, встановіть «Увімкнено» та натисніть «Зберегти».
У **Alert Health** використовуйте «Надіслати тест». Тестуйте фактичне
отримання сповіщення, а не лише статус у SAG.

Канали: Telegram (bot token + chat ID), Slack Incoming Webhook,
Microsoft Teams Power Automate Workflow, Nextcloud Talk OCS API,
HTTPS Webhook та Email через SMTPS 465.

Дані зберігаються в PostgreSQL у `alert_channel_settings`.
Увесь набір параметрів каналу шифрується засобами Laravel (`encrypted:array`);
секрети не з'являються в HTML після збереження. Порожнє поле секрету
залишає попереднє значення. Для ротації введіть нове значення.
Збереження фіксується в аудиті тільки як метадані без значень.
Після збереження налаштування доступні без перезапуску Docker.

Для Teams/Talk/Webhook встановіть точні DNS-імена в полі
«Дозволені DNS-хости». Дозволено лише HTTPS порт 443.
Slack має обмежений вбудований список хостів. Telegram використовує
офіційний Bot API. Вхідні редиректи заборонені.

SMTP: тільки SMTPS 465 із TLS; введіть DNS-ім'я SMTP сервера,
адресу відправника й отримувача. SMTP логін і пароль вводьте разом,
або залиште обидва порожніми для relay без автентифікації.
Реальну доставку SMTP перевіряйте на стенді перед production.

**Сумісність:** якщо канал не зберігали у вебінтерфейсі,
він продовжує використовувати `SAG_CE_ALERT_*` з environment.
Після першого збереження запис БД, включно з «Вимкнено», має пріоритет.

**Перед оновленням:** резервна копія PostgreSQL та `deploy/.env`,
оскільки шифровані налаштування відновлюються лише з початковим
`SAG_CE_APP_KEY`. Міграція:
`php artisan migrate --force`. Не використовуйте `down -v`.

**Обмеження:** DNS rebinding та доступність приватних мереж через DNS
потребують мережевого egress firewall/proxy. Не заявляйте готовність
до production без реальних contract-тестів усіх каналів.
